# 视觉资产与连续分镜模式

当用户要完成课程第 3 课、主视觉基准板、人物/场景/道具资产、6—10 张一致分镜或失败重跑时读取本文件。普通单次提示词任务不加载本模式。

## 能力边界

本模式可以完成工作流路由、三类资产建档、基准板提示词、连续分镜表、节点填写教学、单变量重跑、命名和验收。没有 ComfyUI 执行工具时，必须让学员运行工作流并回传图片；不能把“提示词已写好”说成“图片已生成”或“一致性已验证”。

如果本模式由小说改漫剧项目进入，人物、场景和道具的固定项以项目故事圣经和当前集状态为准，镜头目标以已批准的逐集分镜为准。发现冲突时回到连续性检查，不要为了迁就单张图片擅自改写剧情、人物身份、伤势、服装或关键道具。

## 先确认生产阶段

先判断用户处于哪一段，只推进当前阶段：

1. 还没有基准图：先路由到适合生成或编辑基准图的工作流。
2. 已有候选基准图：先做人物、场景、道具验收，不急着批量分镜。
3. 基准图已通过：再进入“多视角分镜”或用户确认的相邻变体。
4. 已有分镜结果：诊断漂移问题并安排单变量重跑。
5. 已全部通过：整理命名、目录和作业清单。

“多视角分镜”工作流本身读取一张图片，不能在没有基准图时假装它会自动完成全部资产设计。目录当前记录的两个候选是：

- `多视角分镜`：图片节点 `LoadImage`，ID `13`；提示词候选节点 ID `3`、`14`、`20`。
- `多视角分镜-3D摄像机-Edit2511`：图片节点 `LoadImage`，ID `41`；提示词候选节点 ID `68`、`69`、`138`。

必须先让用户确认具体变体，并以用户实际截图或 JSON 的连线、标题和节点 ID 为准。

## 三类视觉资产

资产只分三类。风格属于画面约束，不是独立资产卡。

### 人物资产

记录脸型、年龄感、体型、发型、服装、表情特征和不可变化的身份锚点。不要把姿势或当前背景误当成人物身份。

### 场景资产

记录空间结构、时间、天气、光线、材质和地标物件。至少保留一个能跨镜头辨认空间的锚点，例如窗格、门洞、石碑、桌案或山门。

### 道具资产

记录外形、材质、颜色、尺寸、携带方式、持握位置和与人物的关系。修仙漫剧常见道具包括武器、法宝、令牌、剑匣、卷轴和丹炉。不要只写“仙侠武器”，要写清剑格、剑身、材质、颜色、长度和佩戴或持握位置。

先把用户素材和要求整理为：

```text
人物资产：固定项｜允许变化｜禁止变化
场景资产：固定项｜允许变化｜禁止变化
道具资产：固定项｜允许变化｜禁止变化
视觉约束：时代、媒介感、色彩、光线、材质
```

画幅比例、输出宽高和分辨率属于工作流或节点参数，只记录在项目配置与操作说明中，不写入视觉资产提示词。

## 视觉资产提示词

小说项目完成故事圣经后，必须导出人物、场景和关键道具的视觉资产提示词。完整小说默认分别保存为 `全书-人物资产提示词.md/csv`、`全书-场景资产提示词.md/csv` 和 `全书-道具资产提示词.md/csv`；逐段模式保存为 `第NN段-人物资产提示词.csv`、`第NN段-场景资产提示词.csv` 和 `第NN段-道具资产提示词.csv`，且只列本段新增或发生版本变化的资产。CSV 至少包含：`asset_id`、`asset_type`、`name`、`version`、`source_refs`、`prompt`、`status`。

每条最终提示词写成一个自然连贯、可直接复制的中文长句，可以用逗号和分号连接，但不要写成关键词列表、字段清单、英文标签、括号权重或中英混合标签。人物句子描述同一角色的全身三视图；道具和场景句子只描述一张单图中的固定外观、允许出现的细节和必须避免的变化。

### 人物三视图

- 所有人物资产都必须输出全身三视图：同一角色以正面、标准侧面和背面三种视角等高并列，三幅均从发顶到脚底完整可见，不裁切头部、手臂、腿部、衣摆或鞋履。
- 使用自然直立的中性姿势，手臂与躯干适当分开，避免大动作、遮挡、透视夸张和剧情表演，以便核对体型、服装结构和佩戴位置。
- 三个视角必须保持同一张脸、年龄感、身体比例、发型、服装、鞋履、配饰和道具佩戴方式，不得让侧面或背面自行换装、增减配件或改变发长。
- 一个年龄阶段或一套服装对应一个独立版本和一条提示词；不要在同一张三视图中混合常服、战损服、礼服或不同年龄。

人物提示词示例：

```text
在简洁中性的背景中展示角色林凡的同一套完整人物设定，让同一个角色以正面、标准侧面和背面三种视角等高并列自然站立，三个视角都从发顶到脚底完整呈现且不裁切头部、手臂、腿部、衣摆和鞋履，准确保持十八岁少年清瘦挺拔的体型、黑色高束发、棱角分明的脸型、深灰色交领长袍、黑色护腕、布靴以及腰间旧木剑鞘完全一致，手臂与躯干适当分开以看清服装结构和佩戴位置，背景中不出现剧情场景、文字、水印或其他人物。
```

### 场景与道具单图资产

- 场景资产每项只生成一张单一连续空间参考图，选择最能交代空间结构和地标的主观察机位，清楚呈现入口、纵深、材质、时间、光线与跨镜头锚点；明确要求整张图只有一个完整场景，不分栏、不拼贴、不制作三视图，不在同一张图中重复同一地标。
- 道具资产每项只生成一张单物体参考图，默认使用能同时看清正面与侧面结构的轻微斜侧观察；有精确标签或正面图案时改为正面观察。主体完整可见，保持尺寸关系、轮廓、材质、颜色、纹样、开合结构和损伤状态清楚；明确要求画面只出现一个道具，不复制、不分栏、不拼贴、不加入手持人物或无关陈设。
- 对容易被模型画错的结构使用可观察的几何语言，不用抽象名词代替。例如纸折星应写清“立体折纸星星，有清晰折痕、凸起的五个角和可见厚度，不是平面剪纸”；刘海应写清覆盖眉毛、眼睛和额头的具体范围；服装应写清款式、轮廓、颜色与材质，不只写“时髦”“性感”或“职业装”。

### 禁用内容

视觉资产提示词不得包含：

- 画面比例或方向参数，例如 `1:1`、`16:9`、`9:16`、横版、竖版。
- 像素与分辨率词，例如 4K、8K、UHD、高分辨率。
- 空泛质量词，例如高清、超清、最佳质量、顶级质量、大师杰作、极致画质、电影级画质。
- 采样步数、CFG、种子、放大倍数或节点宽高等界面参数。

这些内容不能决定提示词所生成图片的实际分辨率。需要的画幅、尺寸和清晰化流程应在已确认工作流的节点参数或后处理步骤中单独设置。

### Flux.2 Klein 尺寸与文字实测规则

这些规则来自 Flux.2 Klein 4B 的实际批量资产生产，只在该模型链路或复现同类问题时使用：

- 宽高节点中的目标值不等于最终文件一定精确。潜空间尺寸约束可能静默取整，例如目标宽度一千零八十会输出一千零七十二。生成后必须读取成品文件的实际宽高，不能只看节点设置或缩略图。
- 若交付必须精确到指定宽高，在 `VAEDecode` 后、`SaveImage` 前增加 `ImageScale`，插值使用 `lanczos`，目标宽高填写交付尺寸，裁切关闭；保存节点必须连接缩放后的图像。这个设置只写在工作流参数说明中，不写入提示词。
- Flux.2 Klein 生成精确中文文字可能出现乱码、错字或伪字。凡是墓碑、药瓶标签、班牌、校名、招牌等文字敏感资产，都必须把“文字逐字正确”设为独立质量门，不能因为构图和主体正确就判定通过。
- 第一次文字失败时，只修改文字约束，明确要求引号内原文逐字出现且不出现其他文字；若再次失败，不连续盲目重跑，应保留干净、平整、无遮挡的空白碑面或标签区域，转交文字编辑、局部重绘或后期排字工作流完成，并在验收表标记“结构通过、文字待修”。

### 批量生成顺序

先解析并核对预期资产数量，再从人物、道具和场景中各选择一条代表提示词试跑；人物检查完整全身三视图，道具检查单主体与完整结构，场景检查单一连续空间与实际尺寸，文字资产检查逐字准确。三类代表样本通过后才批量运行。批量结束后逐张检查，不通过的资产按单变量原则生成新版本；失败图移入“未通过候选”目录，正式交付目录只保留当前通过版本。

视觉资产验收时检查：人物是否确为同一角色的完整全身正面、标准侧面和背面，三个视角是否等高且没有裁切，服装与配件是否一致；每个场景是否只有一张连续空间画面且地标、纵深与光线清楚；每个道具是否只有一个完整主体且结构、材质与标签清楚；场景和道具是否没有三视图、分栏、拼贴或重复主体；成品文件实际宽高是否符合工作流参数；规定中文文字是否逐字正确；提示词是否为中文长句并通过禁用词检查。未通过时不要进入主视觉基准板。

## 主视觉基准板

基准板用于证明三类资产能同时成立。生成前明确每张参考图只负责什么，不负责什么；生成后逐项验收：

- 人物一眼可辨认，正面、侧面或后续镜头仍像同一人。
- 场景空间关系清楚，地标物件能在后续镜头中引用。
- 关键道具外形、材质、尺寸和位置稳定，没有复制、消失或换手。
- 没有明显肢体、文字或结构错误。
- 画面留出后续动作和镜头运动空间。

任一项不通过，停留在基准板阶段，不直接生成 6—10 张分镜。

## 连续分镜

从分镜脚本读取镜头目标，不机械套固定景别。首轮通常先做 6 个镜头的最小闭环，再扩到 10 个。每个镜头必须同时包含：

- 镜头编号和叙事目的。
- 景别、机位、动作和构图。
- 继承的人物、场景和道具资产。
- 本镜头唯一允许变化的内容。
- 身份漂移、场景漂移、道具复制或换手等禁止项。

提示词按以下顺序组织，模型家族的具体语法仍以 `prompt-rules.md` 为准：

```text
[继承资产] 人物固定项；场景固定项；道具固定项。
[本镜头] 镜头编号、景别、机位、动作、构图和结束状态。
[必须保持] 身份、服装、空间锚点、道具外形与持握位置。
[禁止] 新增人物、身份漂移、场景漂移、道具复制、换手、消失、乱码或水印。
```

## 单变量失败重跑

先让用户指出失败现象，再把“固定不动”和“本轮只改一项”写清。可修改变量通常是景别、机位、动作、构图、提示词权重或种子中的一个；不要同时换模型、参考图、提示词结构和构图。

每次重跑记录：

```text
失败文件：
失败现象：
保持不动：工作流｜模型｜参考图｜画幅｜核心资产
本轮只改：
新版本号：v02 / v03
对比结论：改善｜无效｜产生新问题
```

## 命名与验收

用户可见文件使用中文名、稳定序号和版本号，例如 `第01段-镜头001-雨巷建立-首帧-v01.png`。文件内容继续使用 `SEG001`、`SH001`、`CHAR001`、`LOC001`、`PROP001` 等稳定 ID。中文文件名避免 `\ / : * ? " < > |`，系统续作文件仍保持固定英文名。建议目录：

```text
第01段/
├─ 01-故事与资产/   资产提示词与资产验收
├─ 02-分镜与首帧/   分镜、首帧提示词与通过验收的首帧
├─ 03-镜头视频/     视频提示词、镜头视频与视频验收
└─ 工作流说明.txt   完整工作流名称和版本
```

最终交付至少包括：1 张主视觉基准板、6—10 张通过验收的分镜、完整工作流名称，以及 1 次失败到修正的记录。
