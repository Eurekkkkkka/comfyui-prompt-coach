# 视觉资产与连续分镜模式

当用户要完成课程第 3 课、主视觉基准板、人物/场景/道具资产、6—10 张一致分镜或失败重跑时读取本文件。普通单次提示词任务不加载本模式。

## 能力边界

本模式可以完成工作流路由、三类资产建档、基准板提示词、连续分镜表、节点填写教学、单变量重跑、命名和验收。没有 ComfyUI 执行工具时，必须让学员运行工作流并回传图片；不能把“提示词已写好”说成“图片已生成”或“一致性已验证”。

如果本模式由小说改漫剧项目进入，人物、场景和道具的固定项以项目故事圣经和当前集状态为准，镜头目标以已批准的逐集分镜为准。发现冲突时回到连续性检查，不要为了迁就单张图片擅自改写剧情、人物身份、伤势、服装或关键道具。

## 先确认生产阶段

先判断用户处于哪一段，只推进当前阶段：

1. 还没有基准图：先路由到适合生成或编辑基准图的工作流。
2. 已有候选基准图：先做人物、场景、道具验收，不急着批量分镜。
3. 基准图已通过：再进入“多视角分镜”或用户确认的相邻变体。
4. 已有分镜结果：诊断漂移问题并安排单变量重跑。
5. 已全部通过：整理命名、目录和作业清单。

“多视角分镜”工作流本身读取一张图片，不能在没有基准图时假装它会自动完成全部资产设计。目录当前记录的两个候选是：

- `多视角分镜`：图片节点 `LoadImage`，ID `13`；提示词候选节点 ID `3`、`14`、`20`。
- `多视角分镜-3D摄像机-Edit2511`：图片节点 `LoadImage`，ID `41`；提示词候选节点 ID `68`、`69`、`138`。

必须先让用户确认具体变体，并以用户实际截图或 JSON 的连线、标题和节点 ID 为准。

## 三类视觉资产

资产只分三类。风格属于画面约束，不是独立资产卡。

### 人物资产

记录脸型、年龄感、体型、发型、服装、表情特征和不可变化的身份锚点。不要把姿势或当前背景误当成人物身份。

### 场景资产

记录空间结构、时间、天气、光线、材质和地标物件。至少保留一个能跨镜头辨认空间的锚点，例如窗格、门洞、石碑、桌案或山门。

### 道具资产

记录外形、材质、颜色、尺寸、携带方式、持握位置和与人物的关系。修仙漫剧常见道具包括武器、法宝、令牌、剑匣、卷轴和丹炉。不要只写“仙侠武器”，要写清剑格、剑身、材质、颜色、长度和佩戴或持握位置。

先把用户素材和要求整理为：

```text
人物资产：固定项｜允许变化｜禁止变化
场景资产：固定项｜允许变化｜禁止变化
道具资产：固定项｜允许变化｜禁止变化
视觉约束：时代、媒介感、色彩、光线、画幅比例
```

## 主视觉基准板

基准板用于证明三类资产能同时成立。生成前明确每张参考图只负责什么，不负责什么；生成后逐项验收：

- 人物一眼可辨认，正面、侧面或后续镜头仍像同一人。
- 场景空间关系清楚，地标物件能在后续镜头中引用。
- 关键道具外形、材质、尺寸和位置稳定，没有复制、消失或换手。
- 没有明显肢体、文字或结构错误。
- 画面留出后续动作和镜头运动空间。

任一项不通过，停留在基准板阶段，不直接生成 6—10 张分镜。

## 连续分镜

从分镜脚本读取镜头目标，不机械套固定景别。首轮通常先做 6 个镜头的最小闭环，再扩到 10 个。每个镜头必须同时包含：

- 镜头编号和叙事目的。
- 景别、机位、动作和构图。
- 继承的人物、场景和道具资产。
- 本镜头唯一允许变化的内容。
- 身份漂移、场景漂移、道具复制或换手等禁止项。

提示词按以下顺序组织，模型家族的具体语法仍以 `prompt-rules.md` 为准：

```text
[继承资产] 人物固定项；场景固定项；道具固定项。
[本镜头] 镜头编号、景别、机位、动作、构图和结束状态。
[必须保持] 身份、服装、空间锚点、道具外形与持握位置。
[禁止] 新增人物、身份漂移、场景漂移、道具复制、换手、消失、乱码或水印。
```

## 单变量失败重跑

先让用户指出失败现象，再把“固定不动”和“本轮只改一项”写清。可修改变量通常是景别、机位、动作、构图、提示词权重或种子中的一个；不要同时换模型、参考图、提示词结构和构图。

每次重跑记录：

```text
失败文件：
失败现象：
保持不动：工作流｜模型｜参考图｜画幅｜核心资产
本轮只改：
新版本号：v02 / v03
对比结论：改善｜无效｜产生新问题
```

## 命名与验收

文件名使用 `镜头号_内容_版本号.png`，例如 `S01_雨巷建立_v01.png`。建议目录：

```text
03_visual-assets/
├─ 00_reference/   主视觉基准板
├─ 01_storyboard/  通过验收的分镜
├─ 02_failed/      失败图与重跑记录
└─ workflow.txt    完整工作流名称和版本
```

最终交付至少包括：1 张主视觉基准板、6—10 张通过验收的分镜、完整工作流名称，以及 1 次失败到修正的记录。
