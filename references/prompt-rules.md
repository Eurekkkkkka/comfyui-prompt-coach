# 提示词生成规则

只在具体工作流已经确认后读取本文件。先从工作流目录确定模型家族、素材顺序、提示词节点和负向节点，再套用对应规则。

## 1. 通用拆解

先把需求整理为以下字段，再按模型家族组合，不必把字段名全部写进最终提示词：

- 任务：生成、修改、替换、保留、消除、修复、迁移或扩展。
- 主体：人物、商品、动物、文字或场景。
- 身份锚点：脸、发型、服装、商品结构、品牌文字等必须保持一致的特征。
- 动作：姿势、表情、运动幅度和先后顺序。
- 场景：环境、背景、时间、天气和氛围。
- 镜头：景别、角度、焦段感、运动和构图。
- 视觉：光线、色彩、材质、清晰度和风格。
- 保留：不得变化的内容。
- 修改：需要发生变化的内容。
- 禁止：水印、字幕、额外人物、结构变形等。

构建视觉资产包时，资产固定分为人物、场景和道具；风格只作为时代、媒介感、色彩、光线、材质和画幅等视觉约束，不单独作为资产。

只写模型能够执行且当前工作流提供输入的内容。不要把采样步数、CFG、分辨率等界面参数混进自然语言提示词，除非对应工作流明确要求文本控制。

## 2. Qwen Image 与 Qwen Image Edit

### 文生图

优先使用中文结构化自然语言，顺序为：主体 → 场景 → 构图镜头 → 光线色彩 → 材质细节 → 文字排版 → 质量约束。

文字必须逐字写明，并使用中文引号标记。涉及海报时，同时说明文字层级、位置、字体气质、留白和可读性。

### 单图编辑

使用“根据图像 1”或“编辑输入图像”的明确指令：

1. 先写要修改的对象和动作。
2. 再写必须保留的身份、构图、背景或材质。
3. 最后写禁止新增或改变的内容。

避免只写风格词。编辑任务必须出现可执行动词，例如“替换”“移除”“改为”“保持”“修复”。

### 多图编辑

先确认每张图的角色，再使用：

- 图像 1：主体或底图。
- 图像 2：服装、脸、商品或风格参考。
- 图像 3：姿势、构图或背景参考。

最终指令必须写清“使用图像 2 的什么，应用到图像 1 的哪里，同时保持图像 1 的什么”。不要写“融合两张图”这种无方向指令。

## 3. Flux Kontext 与 Klein

使用简洁的编辑命令。先写目标修改，再写保持条件；一句话能说清就不堆叠形容词。

推荐结构：

> 将/移除/替换 [明确对象或区域]，生成 [目标结果]；保持 [人物身份、构图、光线、背景等] 不变，不新增 [禁止项]。

如果目录中的默认提示词是英文，最终优先输出英文，并用中文解释含义；若用户明确要求中文，可以输出中文版本，但不要同时把双语都粘进节点。

局部消除必须描述目标区域的视觉特征或遮罩颜色，并要求用周围背景自然补全。

## 4. Z-Image 与通用文生图

采用从主体到画面的连续描述：主体身份和外观 → 动作 → 场景 → 构图 → 光线 → 材质 → 风格 → 清晰度。

避免互相冲突的审美词，例如同时要求“极简纯色背景”和“复杂繁华街景”。需要亿级像素或超清输出时，提示词关注细节层级和材质真实性，不在提示词中承诺实际像素数。

## 5. Ideogram

同时控制画面和排版：

- 精确文字内容，逐字检查。
- 主标题、副标题、正文或角标的层级。
- 文字位置、对齐、方向和留白。
- 字体气质，不虚构受版权保护的具体字体文件。
- 背景与文字的对比度。
- 禁止乱码、错别字、重复文字和变形字。

长文案先建议用户压缩；不要把大段正文塞进一张海报。

## 6. Wan、Animate、InfiniteTalk 与 VACE

### 图生视频

图片已经提供人物和场景时，提示词重点写“接下来发生什么”，不要重复堆叠静态外貌。

推荐顺序：主体初始状态 → 动作变化 → 表情和视线 → 场景动态 → 镜头运动 → 结束状态 → 连贯性限制。

### 分秒时间线

只有工作流或用户确实需要分段控制时才写时间：

> 0–2 秒：……；2–4 秒：……；4–5 秒：……。

相邻时段必须能够自然衔接，不让同一人物瞬间换位置、服装或朝向。

### 首尾帧

说明从首帧到尾帧的过渡过程，而不是分别描述两张图。明确主体如何移动、镜头如何变化、哪些元素必须连续。

### 动作迁移

参考视频决定动作，提示词主要控制主体身份、动作幅度、表情和不允许的额外动作。若工作流已有固定人物关键词，不随意删除。

### 对口型与唱歌数字人

提示词控制头部、表情、上半身动作和镜头稳定性；音频决定口型。说话场景使用克制的自然动作，唱歌场景才增加节奏性和动作幅度。

### VACE 与视频局部处理

提示词描述遮罩区域应被替换成什么，以及如何与相邻帧背景连续。负向提示词保留工作流原有的闪烁、字幕、模糊和结构错误约束，除非用户有明确理由修改。

## 7. MiniMax H3

### T2V

完整描述人物、场景、动作、镜头和声音氛围。先确定单镜头还是多镜头；没有导演台需求时保持单镜头清晰可执行。

### I2V

以输入图作为身份与场景锚点，主要描述运动和镜头。不要重复改写人物外貌，除非用户要求改变。

### R2V

明确各参考图分别提供主体、商品、服装、场景或风格。强调跨镜头一致性，不让参考对象混淆。

提示词可采用：场景建立 → 主体行为 → 摄像机运动 → 光影变化 → 结束画面。涉及对白时，把对白内容和画面动作分开写清。

### H3 Director 导演台

- 把最终提示词写入 `MiniMaxH3Director` 节点的 `global_prompt`，先依据工作流的 `task_type` 确认 T2V、I2V、FL2V、R2V、V2V 或 RV2V，不能混用素材规则。
- T2V 不放参考素材；I2V 放首帧图；FL2V 放首帧和尾帧；R2V 可放图片、视频或音频参考；V2V 放源视频；RV2V 放源视频并可追加图片、视频或音频参考。
- R2V、V2V 和 RV2V 必须保留导演台显示的引用顺序与英文标签，例如 `<Picture 1>`、`<Video 1>`、`<Audio 1>`，不要自行改号或把标签翻译成中文。
- `global_prompt` 按“主体与场景 → 动作与表演 → 镜头运动 → 光影与节奏 → 声音或对白 → 收束画面”组织。使用参考素材时明确每个标签负责身份、场景、动作、风格或声音中的哪一项。
- 默认 24 fps、124 帧约为 5 秒。只有用户明确要改变时长时才建议修改帧数，并提醒时长约等于“总帧数 ÷ 帧率”。

### H3 提示词优化流程

以下方法参考 [1038lab/ComfyUI-MiniMax-H3-Promptor](https://github.com/1038lab/ComfyUI-MiniMax-H3-Promptor) 的“视觉分析与提示词结构化分离”思路，并重新适配课程工作流。只提炼方法，不依赖或打包该项目的节点与代码；上游示例若与当前工作流冲突，以用户实际节点和 `task_type` 为准。

#### 1. 先分析素材，再写提示词

不要把图片或视频的全部细节无差别塞进提示词。先给每份素材指定分析任务：

- 人物图：身份、五官、发型、体型、服装；动作和背景默认不继承。
- 表演图：姿态、表情、视线和身体动作；身份仅在用户明确要求时继承。
- 商品或道具图：形状、材质、颜色、文字和结构；背景、手势和构图默认不继承。
- 场景或风格图：空间、材质、光线、色彩、镜头气质；图中偶然出现的人物默认不继承。
- 动作视频：动作顺序、速度、重心、惯性、节奏和表演时机。
- 镜头视频：景别变化、机位、运动路径、剪辑节奏和空间关系。
- 音频：说话人音色、台词、情绪、节拍或音效用途；必须绑定到明确人物或事件。

素材分析只记录看得见或听得见的事实。用户的创作要求与素材事实分开整理，再在下一步组合。

#### 2. 给每份参考素材划定权限

在提示词开头建立“参考素材职责表”，每个标签只控制一组明确属性。例如：

```text
[REFERENCE USE]
<Picture 1> 只定义女主角的脸部、发型和体型，不继承原图背景、姿势与服装。
<Picture 2> 只定义红色皮夹克的版型、材质和颜色。
<Video 1> 只提供动作节奏与身体运动，不继承人物身份和场景。
<Audio 1> 只提供女主角的声音与台词节奏。
```

必须使用当前导演台实际显示的 `<Picture N>`、`<Video N>`、`<Audio N>`。不要照搬其他节点可能使用的 `Image1`、`Video1` 或 `Audio1` 写法。

#### 3. 按稳定信息到动态信息组织

复杂任务优先按以下顺序组织；没有的部分直接省略：

1. `[REFERENCE USE]`：每份素材负责什么、不负责什么。
2. `[IDENTITY / CONTINUITY LOCKS]`：人数、身份、服装、道具、声音归属和连续性。
3. `[SCENE]`：地点、时间、人物目标、情绪变化和最终状态。
4. `[DIALOGUE]`：说话人、原句、语言、语气和出现时段。
5. `[SCREEN GEOGRAPHY]`：多人站位、左右关系、视线和运动轴线。
6. `[SHOT LIST]`：按时间排列的景别、镜头行为、可见动作和结束画面。
7. `[ACTING]`：表情、重心、手势、呼吸和表演强度。
8. `[LIGHT AND IMAGE]`：光源、色彩、材质、景深和画面质感。
9. `[CAMERA]`：允许的镜头运动及限制。
10. `[PRODUCTION SOUND]`：环境声、动作音效、对白清晰度和音乐策略。
11. `[NEGATIVES]`：只写当前任务最可能出现的错误。

稳定事实必须放在动作时间线之前；表演、光线、镜头、声音和负向约束放在时间线之后。简单单镜头不必机械套满所有标题。

#### 4. 针对模式优化

- T2V：不写参考素材段，完整定义人物、场景和可执行动作。
- I2V：第一段必须从上传图片的构图、人物、服装、道具和光线自然起步，主要描述之后发生的运动；不要凭空增加新人物。
- FL2V：明确首帧与尾帧分别由哪张图控制，用一个连续、因果明确的动作连接两端；优先单一长镜头，避免硬切、瞬移、淡入淡出或交叉溶解。
- R2V：逐一声明每份图片、视频或音频的职责，不能用“参考所有素材”代替明确分工。
- V2V：把源视频作为动作、时间线、镜头和遮挡关系的主版本，只描述需要增强或改变的部分。
- RV2V：先声明源视频中必须保留的主体、场景、时序、机位、对白和环境声，再说明参考素材只替换什么。换人、换装、换背景或换声音时，分别写清 `[EDIT]` 和 `[PRESERVE]`。

#### 5. 时间、镜头、对白与声音

- 多段动作使用连续且不重叠的时间范围，例如 `0–2s`、`2–5s`。每段至少包含景别、镜头行为、人物动作和结束状态；有对白时留出自然说话与反应时间。
- 镜头运动写进完整动作句，说明速度、幅度和目标，例如“镜头以小幅慢速向她手中的信件推进”。不要在句尾堆“推镜、电影感、4K、大师级”等孤立标签。
- 区分变焦与机位移动：Zoom 改变焦距，Push/Pull 改变相机位置；Pan/Tilt 是旋转，Tracking 跟随主体，Arc 围绕主体运动。
- 对白写清“谁说、准确台词、语言、语气、时间段”；引用声音时再写“哪份音频提供声音、最终如何混音”。旁白必须说明画外音，并要求画面人物嘴唇保持闭合。
- 声音分成环境声、动作音效、对白清晰度和音乐策略四层。用户没有要音乐时，明确“无背景音乐”。
- 屏幕中必须准确生成的标题、招牌或界面文字使用英文双引号包住原文，并提醒文字生成可能不稳定。

#### 6. 输出前压缩与检查

- 只保留可见、可听、可执行的描述，删除同义重复、空泛质量词和互相冲突的镜头指令。
- 负向提示词保持短而具体，优先防止身份漂移、人数变化、服装替换、道具重复、视线错误、无动机切镜、字幕和意外音乐。
- 参考项目按 7,000 字符进行上限校验；课程工作流没有显示更小限制时，可把 7,000 字符作为安全上限。若实际节点显示其他限制，以节点为准。
- 最终代码块内只放要粘贴进 `global_prompt` 的内容，不附带解释、Markdown 标题或复制说明。

## 8. Bernini 与 LTX 导演工作流

使用导演式表达，但保持可执行：

- 镜头编号或时间段。
- 景别和机位。
- 摄像机运动。
- 人物调度和表演。
- 场景变化和转场。
- 光线、节奏和收束画面。

多镜头时保证人物身份、服装、道具方向和空间关系连续。不要在一个短镜头里塞入过多场景切换。

## 9. 修复、放大与去水印

### 修复与放大

默认以保真为优先：恢复真实皮肤、材质、边缘和细节；保持人物身份、构图、比例、服装和背景不变；禁止美颜过度、重绘五官、添加饰品或改变年代特征。

### 老照片

区分修复、上色和动态化。用户没要求上色时不要自动上色；用户没要求动起来时不要生成动作指令。

### 去水印或万物消除

说明要移除的具体对象、文字、颜色区域或遮罩区域，并要求根据周围纹理、光影和透视自然补全。不要许诺恢复水印下真实存在但不可见的原始内容。

## 10. 声音与台词

- 单人 TTS：输出纯台词，不添加舞台说明，除非节点支持情绪标签。
- 双人对话：严格沿用工作流要求的说话人标签，例如 `[S1]`、`[S2]`。
- 配音二创：保留人物关系和语气，控制句长，避免一口气无法读完的长句。
- 变声和声音克隆：提示用户上传干净参考音频；不要声称提示词能弥补严重噪声或多人混音。
- AI 翻唱：歌词、参考音色和伴奏是不同输入，不把它们混成一段提示词。

## 11. 反推提示词

用户使用反推工作流时，先说明输出是对画面的结构化描述，不是原始创作者提示词的恢复。图片反推关注主体、场景、构图、光线、材质和风格；视频反推增加动作、镜头和时间变化。

## 12. 负向提示词

只有工作流确实提供负向节点时才生成或修改负向提示词。

- 优先保留工作流已有的通用质量约束。
- 只补充与本次任务直接相关的禁止项。
- 不把正向要求换一种说法全部堆进负向提示词。
- 不加入与用户需求无关的敏感词或过度限制，以免压制生成结果。
- 对视频重点防止闪烁、跳变、身份漂移、肢体畸变、静止画面、字幕和水印。
