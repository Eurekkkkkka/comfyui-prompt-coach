# 提示词生成规则

只在具体工作流已经确认后读取本文件。当前节点位置、图序与是否需填写以 workflow-catalog.md 链接的 2026-09-20 教程为准；旧名称不作为当前可用入口。先从工作流目录确定模型家族、素材顺序、提示词节点和负向节点，再套用对应规则。

## 1. 通用拆解

先把需求整理为以下字段，再按模型家族组合，不必把字段名全部写进最终提示词：

- 任务：生成、修改、替换、保留、消除、修复、迁移或扩展。
- 主体：人物、商品、动物、文字或场景。
- 身份锚点：脸、发型、服装、商品结构、品牌文字等必须保持一致的特征。
- 动作：姿势、表情、运动幅度和先后顺序。
- 场景：环境、背景、时间、天气和氛围。
- 镜头：景别、角度、焦段感、运动和构图。
- 视觉：光线、色彩、材质和风格。
- 保留：不得变化的内容。
- 修改：需要发生变化的内容。
- 禁止：水印、字幕、额外人物、结构变形等。

构建视觉资产包时，资产固定分为人物、场景和道具；风格只作为时代、媒介感、色彩、光线和材质等视觉约束，不单独作为资产。小说项目的视觉资产提示词必须使用中文长句；人物必须为从发顶到脚底完整可见的正面、标准侧面和背面全身三视图，道具和场景则每项只生成一张单图，不得做三视图、分栏、拼贴或重复主体；即使模型家族通常偏好英文或关键词格式，这项规则仍优先。

只写模型能够执行且当前工作流提供输入的内容。不要把画面比例、采样步数、CFG、种子、像素、分辨率或放大倍数等界面参数混进自然语言提示词。不要添加 4K、8K、UHD、高清、超清、最佳质量、大师杰作等参数化或空泛质量词；实际画幅和分辨率只能在工作流节点参数中设置。工作流目录里记录的旧示例即使包含这些词，也不得原样复制到新提示词。

## 2. Qwen Image 与 Qwen Image Edit

### 文生图

优先使用中文结构化自然语言，顺序为：主体 → 场景 → 构图镜头 → 光线色彩 → 材质细节 → 文字排版。

文字必须逐字写明，并使用中文引号标记。涉及海报时，同时说明文字层级、位置、字体气质、留白和可读性。

### 单图编辑

使用“根据图像 1”或“编辑输入图像”的明确指令：

1. 先写要修改的对象和动作。
2. 再写必须保留的身份、构图、背景或材质。
3. 最后写禁止新增或改变的内容。

避免只写风格词。编辑任务必须出现可执行动词，例如“替换”“移除”“改为”“保持”“修复”。

### 多图编辑

先确认每张图的角色，再使用：

- 图像 1：主体或底图。
- 图像 2：服装、脸、商品或风格参考。
- 图像 3：姿势、构图或背景参考。

最终指令必须写清“使用图像 2 的什么，应用到图像 1 的哪里，同时保持图像 1 的什么”。不要写“融合两张图”这种无方向指令。

## 3. Flux Kontext 与 Klein

使用简洁的编辑命令。先写目标修改，再写保持条件；一句话能说清就不堆叠形容词。

推荐结构：

> 将/移除/替换 [明确对象或区域]，生成 [目标结果]；保持 [人物身份、构图、光线、背景等] 不变，不新增 [禁止项]。

如果目录中的默认提示词是英文，最终优先输出英文，并用中文解释含义；若用户明确要求中文，可以输出中文版本，但不要同时把双语都粘进节点。

局部消除必须描述目标区域的视觉特征或遮罩颜色，并要求用周围背景自然补全。

使用 Flux.2 Klein 4B 文生图制作人物、场景或道具资产时，仍使用中文自然长句，但要把抽象形容词改写成可观察结构，例如刘海遮到哪里、服装是什么轮廓和材质、折纸是否有折痕与厚度。人物使用完整全身三视图；道具只出现一个完整物体；场景只出现一个连续空间，并在句末明确禁止多格、拼贴、三视图和重复主体。

该模型的潜空间可能把节点宽高静默取整，且精确中文文字容易出现错字或伪字。输出后必须检查文件实际宽高和规定文字；精确尺寸用解码后的图像缩放节点处理，精确文字连续两次失败后转文字编辑或局部重绘，不把尺寸和像素写进提示词，也不把乱码结果判定为通过。

使用 `图生图-FLUX.2 Klein 4B 多图参考编辑` 时，固定素材职责：Image 1 是主体或底图，负责身份、姿势、构图与原环境；Image 2 只提供服装、商品、场景或风格属性。编辑指令先写把 Image 2 的哪些属性应用到 Image 1，再写 Image 1 必须保持不变的内容，不要只写“融合两张图”。

## 4. Z-Image 与通用文生图

采用从主体到画面的连续描述：主体身份和外观 → 动作 → 场景 → 构图 → 光线 → 材质 → 风格。

避免互相冲突的审美词，例如同时要求“极简纯色背景”和“复杂繁华街景”。需要更大输出尺寸或后期清晰化时，在工作流参数和后处理步骤中处理，不在提示词中写像素数、分辨率或空泛质量词。

### Anima 动漫文生图

用中文自然长句明确角色外观、动作、场景、构图、光线和动漫媒介特征。画幅与像素留在尺寸节点；人物资产仍必须是完整全身三视图，场景与道具仍各只生成一张单图。不要只写“日漫风”“二次元”等宽泛标签，也不要用具体在世画师姓名代替可观察的线条、上色和光影特征。

## 5. Ideogram

同时控制画面和排版：

- 精确文字内容，逐字检查。
- 主标题、副标题、正文或角标的层级。
- 文字位置、对齐、方向和留白。
- 字体气质，不虚构受版权保护的具体字体文件。
- 背景与文字的对比度。
- 禁止乱码、错别字、重复文字和变形字。

长文案先建议用户压缩；不要把大段正文塞进一张海报。

## 6. Wan、Animate、InfiniteTalk 与 VACE

### 图生视频

图片已经提供人物和场景时，提示词重点写“接下来发生什么”，不要重复堆叠静态外貌。

推荐顺序：主体初始状态 → 动作变化 → 表情和视线 → 场景动态 → 镜头运动 → 结束状态 → 连贯性限制。

### 分秒时间线

只有工作流或用户确实需要分段控制时才写时间：

> 0–2 秒：……；2–4 秒：……；4–5 秒：……。

相邻时段必须能够自然衔接，不让同一人物瞬间换位置、服装或朝向。

### 首尾帧

说明从首帧到尾帧的过渡过程，而不是分别描述两张图。明确主体如何移动、镜头如何变化、哪些元素必须连续。

### 动作迁移

参考视频决定动作，提示词主要控制主体身份、动作幅度、表情和不允许的额外动作。若工作流已有固定人物关键词，不随意删除。

### 对口型与唱歌数字人

提示词控制头部、表情、上半身动作和镜头稳定性；音频决定口型。说话场景使用克制的自然动作，唱歌场景才增加节奏性和动作幅度。

### VACE 与视频局部处理

提示词描述遮罩区域应被替换成什么，以及如何与相邻帧背景连续。负向提示词保留工作流原有的闪烁、字幕、模糊和结构错误约束，除非用户有明确理由修改。

## 7. MiniMax H3

先完整读取 [H3 镜像适配](minimax-h3-prompting.md)，随后嵌套读取 [用户提供的子技能](minimax-h3-official/SKILL.md) 与对应 Base/Ref2VA 规范。模式专用文件决定结构、语言、对白和引用；实际教程决定粘贴位置、素材连接、时长及界面句柄。

H3 不沿用通用的自由段落格式，也不把 `[REFERENCE USE]`、`[SHOT LIST]` 等策划标签当作最终模型字段。已有完整结构化提示词通过检查后，在独立重写节点选 Validate 可避免二次模型改写；具体行为见镜像适配。

## 8. Bernini 与 LTX 导演工作流

使用导演式表达，但保持可执行：

- 镜头编号或时间段。
- 景别和机位。
- 摄像机运动。
- 人物调度和表演。
- 场景变化和转场。
- 光线、节奏和收束画面。

多镜头时保证人物身份、服装、道具方向和空间关系连续。不要在一个短镜头里塞入过多场景切换。

LTX 2.3 放大工作流的文本只用于约束运动与细节恢复：描述源视频中本来存在的主体、动作和镜头，并要求保持身份、构图、节奏与时长，不新增剧情、人物、道具、字幕或镜头切换。清晰度、输出尺寸和放大倍数在节点中设置，不写进提示词。

## 9. 修复、放大与去水印

### 修复与放大

默认以保真为优先：恢复真实皮肤、材质、边缘和细节；保持人物身份、构图、比例、服装和背景不变；禁止美颜过度、重绘五官、添加饰品或改变年代特征。

### 老照片

区分修复、上色和动态化。用户没要求上色时不要自动上色；用户没要求动起来时不要生成动作指令。

### 去水印或万物消除

说明要移除的具体对象、文字、颜色区域或遮罩区域，并要求根据周围纹理、光影和透视自然补全。不要许诺恢复水印下真实存在但不可见的原始内容。

## 10. 声音与台词

- 单人 TTS：输出纯台词，不添加舞台说明，除非节点支持情绪标签。
- 双人对话：严格沿用工作流要求的说话人标签，例如 `[S1]`、`[S2]`。
- 配音二创：保留人物关系和语气，控制句长，避免一口气无法读完的长句。
- 变声和声音克隆：提示用户上传干净参考音频；不要声称提示词能弥补严重噪声或多人混音。
- AI 翻唱：歌词、参考音色和伴奏是不同输入，不把它们混成一段提示词。

## 11. 反推提示词

用户使用反推工作流时，先说明输出是对画面的结构化描述，不是原始创作者提示词的恢复。图片反推关注主体、场景、构图、光线、材质和风格；视频反推增加动作、镜头和时间变化。

## 12. 负向提示词

只有工作流确实提供负向节点时才生成或修改负向提示词。

- 优先保留与结构、身份和任务直接相关的禁止项；视觉资产提示词不得保留“低分辨率”“低画质”等分辨率或空泛质量词。
- 只补充与本次任务直接相关的禁止项。
- 不把正向要求换一种说法全部堆进负向提示词。
- 不加入与用户需求无关的敏感词或过度限制，以免压制生成结果。
- 对视频重点防止闪烁、跳变、身份漂移、肢体畸变、静止画面、字幕和水印。

## 13. Krea 2、MiniMax Music 3 与 Qwen3-TTS

### Krea 2

- `文生图丨Krea2`：在当前 #120 CR Text 的 text 提示词框写中文自然长句，顺序为主体、动作、场景、构图、光线、材质和风格。画幅与尺寸在独立尺寸节点设置，不写进提示词。
- 构建小说视觉资产时，人物仍用完整全身三视图；场景与道具各只生成一张单图。
- `角色资产四视图丨Krea2`：不要求学员填写提示词。上传一张角色图后直接运行，保留内部固定指令；负向节点标题标注 `leave empty`，必须保持为空。输出后检查是否同时得到脸部特写、正面、侧面和背面四种视图。

### MiniMax Music 3

只填写 `brief`、`lyrics` 和 `constraints`：

- `brief` 写曲风、乐器、速度、节奏、唱法、情绪和动态变化。
- `lyrics` 保留 `[Verse]`、`[Chorus]` 等实际段落结构；纯音乐时明确无歌词或按节点约定留空。
- `constraints` 只写必须遵守的长度、语言、禁用元素等边界。
- 普通创作使用 Rewrite；只有手里已经有完整、符合官方结构的 Caption 时才使用 Passthrough。
- 不用在世艺人姓名代替音色或曲风，改写为可听见的声音特征。

### Qwen3-TTS

- 声音克隆：上传单人、干净、无配乐的参考音频；在 `target_text` 对应的上游输入框填写新台词。参考文本可由工作流转写，语言应与台词一致。
- 声音设计：`text` 填最终台词；`instruct` 写年龄、性别、音高、音色、语速、口音、情绪和使用场景，用可听见的特征描述，不引用真人姓名。
- LUFS 标准化工作流没有提示词输入，只上传音频并检查响度参数和输出结果，不为它虚构提示词。
