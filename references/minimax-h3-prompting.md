# MiniMax H3：嵌套子技能与镜像填写适配

适用：实际节点或模型家族确认为 H3。核对日期：2026-09-20。文件名含 MiniMax 不足以判定 H3；本镜像部分去水印工作流实际使用 Wan。MiniMax Music 3 也不使用本规则。

## 必须读取的嵌套技能

本包完整内嵌用户提供、指定为官方的 `minimax-h3-prompt.zip`，内容不改写。原包内部 name 为 `h3-video-prompt-enhancer`，保留其作者与许可字段；来源和哈希见 [来源记录](h3-source.md)。不要求另外安装同名外部 skill，也不从全局旧副本替代读取。

生成 H3 提示词时依次读取：

1. [子技能 SKILL.md](minimax-h3-official/SKILL.md)。
2. 按实际素材用途读取 [Base 规范](minimax-h3-official/references/base-multishot-format.md) 或 [Ref2VA 规范](minimax-h3-official/references/ref2va-format.md)。不能只读本文件的摘要就声称调用了官方规则。
3. 复杂创作需要增强镜头、节奏或连续性时，读取 [创作示例](minimax-h3-official/references/creative-showcase.md) 的有关片段；示例不是用户要求，不能把示例人物、对白或剧情带入新任务。
4. 从 [当前目录](workflow-catalog.md) 打开本次工作流教程，核对真正可编辑入口。

规则分工：用户要求决定内容；原包的模式参考文件决定最终 H3 格式；本适配与当前工作流决定字段、时长参数、素材接线和界面句柄。原包内部“只输出字段”和“代码块交付”的表述分别适用于可粘贴正文与对话展示：代码块内只有提示词，块外说明位置。若发现原包摘要与对应模式规范不一致，优先对应模式规范并指出必要假设。

## 模式先按用途判断

| 素材用途 | 模式 | 完整规范 |
|---|---|---|
| 纯文字，无锚点素材 | T2VA | Base |
| 一张首帧 | I2VA | Base |
| 首帧加尾帧 | FL2VA | Base |
| 仅尾帧 | L2VA | Base；仅实际节点支持时使用 |
| 人物、风格、动作、声音参考，或源视频编辑/续写 | Ref2VA | Ref2VA |

参考人物图不等于首帧。视频携带声音不自动产生 `<Audio N>`；只有实际音频输入存在时才建立音频引用。素材顺序按接到模型的插口顺序或节点编译后编号，不按文件名猜。

原包规范的单段时长为 4—15 秒整数。这是本次嵌套提示词规范范围，不等于所有界面都只允许这个范围。镜像 T2V 的 #136 和 I2V 的 #138 当前保存为 2 秒：按该规范制作时先建议改到范围内，并同步重写器时长；不能一边给 6 秒提示词一边让实际节点生成 2 秒。单节点创作台快照镜头卡默认 6 秒，沿用实际卡片值；多卡总时长与单卡时长分开计算。帧数可能取整，生成后核对实际时长。

## 三类填写路线

### 单节点创作台：MiniMaxH3Creator #2

- 单卡：填该镜头卡的大文本框。多卡：全局只填所有卡共享的角色、风格、空间与连续性约束，各卡填写独有动作、镜头、声音和结束状态。
- 添加素材并选择首帧、尾帧或参考角色，使用界面实际生成的 `@img-N`、`@vid-N`、`@aud-N` 或角色句柄。只有已存在的句柄可以引用；不要假定新素材一定是 `@img-1`。
- 先按子技能设计完整 H3 内容，再将素材引用映射为界面句柄。该节点编译时将句柄转换为 H3 编号并补首尾帧对齐；不要重复手填对齐行或另造主体编号。使用角色表时，主体定义与引用遵守节点生成的角色映射。
- 节点没有外部输入输出线，素材、时间线与成片都在内部。`creator_data` 是界面状态，不让学员手工编辑。
- 当前节点已支持多个模型家族，先确认该镜头卡为 H3；切到其他家族后不能强套 H3 六段结构。
- 连续模式由节点传递上一段尾帧；新卡是否续接、是否另有首尾帧必须在界面核对，不能同时冲突指定。

### H3 Director：MiniMaxH3Director #5

先核对 `task_type`，再在 `global_prompt` 填对应模式的最终正文；素材在导演台内添加。已有外部 group 接入时可能覆盖内部素材卡，按实际线路判断。根据界面实际编号引用 `<Picture N>`、`<Video N>`、`<Audio N>`。不要套单节点创作台的句柄规则，也不凭旧目录指定已更名的模型文件。

### 独立 T2V / I2V / R2V：MiniMaxH3PromptRewriter

| 工作流 | 创作输入 | 重写器 |
|---|---|---|
| T2V | #119.prompt | #119 |
| I2V | #141 CR Text.text | #121 |
| R2V | #138 PrimitiveStringMultiline.value | #142 |
| 名为“视频修改-MiniMax-H3-R2V多参考” | #138.value；当前仅参考图生成 | #142 |

两种交付情况要区分：

- 用户给原始创意，需要节点重写：保留 `Rewrite | 官方 H3 Skill 重写`，正文输入原始需求；子技能用于组织必要信息与检查结果。
- Agent 已按嵌套子技能交付完整、通过人工检查的结构化提示词：建议选 `Validate | 只校验`，将正文放入上表入口，避免再经一次模型改写。当前节点源码中 Validate 返回原文并生成报告；无需拆线绕过节点。

`reference_map` 只列实际接入素材的职责，`constraints` 放保持项与禁止项；生成节点的 prompt 若已接线，不修改它的旧 widget 值。校验报告是辅助检查，不保证素材连线、引用和语义都正确；Agent 仍须核对输入。报告有实质错误时先修正再生成，不能把“出现报告”当通过。

当前 R2V 两个文件的示例都出现 `<Audio 1>`，但音频插口未连接；没有实际音频时必须删除该引用。名为视频修改的条目还没有连接源视频，不能向学员承诺它能直接编辑上传视频。需要 V2V/RV2V 时路由到实际提供源视频入口的导演台或创作台。

## 输出与交付检查

Base 的核心字段为 `integrated_multimodal_description`、`overall_soundscape`、`non_diegetic_music`；Ref2VA 的六段字段与固定标记必须完整按原包规范生成，不自行改为中文字段或 `[REFERENCE USE]` 等替代格式。

- 模型描述按子技能使用英文；用户对白、歌词、画面文字保留原语言与原句，不翻译。
- 首镜不添加切镜时间戳，后续时间戳严格递增且在单段时长内；每镜一个主动作，跨镜继承身份、服装、道具与状态。
- 对白语言标签放在 `<d>` 内，身份和说话方式在外；旁白注明画面人物嘴唇闭合。
- Ref2VA 每个引用必须有稳定含义、真实素材和对应保留分析；不要凭标题创造视频/音频引用。
- 可粘贴正文不包含节点 ID、解释、画幅尺寸或采样参数。块外另给工作流、字段、素材映射、时长和运行步骤。
- 课程输出外壳仍按课卡，H3 正文与当前操作位置使用本适配。旧课程示例可以展示，但不能把历史参数和节点位置当当前事实。
