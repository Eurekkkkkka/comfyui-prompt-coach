# MiniMax H3 提示词与单节点创作台

当用户已确认 MiniMax H3 工作流、要写 H3 视频提示词，或小说生产进入 H3 视频阶段时完整读取本文件。本规则以用户提供的 `minimax-h3-prompt.zip` 为提示词规范基线，并按镜像中 2026-09-01 的 6 个正式 H3 工作流做了适配，包括单节点创作台、Director 和官方 `MiniMaxH3PromptRewriter` 路线。

## 先识别工作流代际

### 最新：单节点创作台

- 完整名称：`Minimax-H3单节点创作台`
- 文件：`MiniMax H3/Minimax-H3单节点创作台.json`
- 节点：`MiniMaxH3Creator`，快照中的节点 ID 为 `2`
- 节点没有输入、输出连线；素材、提示词、镜头卡、时间线和成片预览都在节点内部完成。
- 单镜头时把提示词写入唯一镜头卡的大文本框，不要写到全局提示词。
- 两个或更多镜头卡时，全局提示词只放每段都继承的身份、风格、场景基线和连续性锁；每张镜头卡只写该段独有的动作、镜头、声音和结束状态。
- 在节点内部添加素材，并使用界面生成的 `@img-N`、`@vid-N`、`@aud-N` 或角色句柄。不要让学员手写 `<Picture N>`、`<Video N>`、`<Audio N>`：节点会在排队时按实际素材顺序自动替换，手写序号会在增删或重排素材后错绑。
- 素材角色决定模型路由。首帧、尾帧属于 Base/FL2VA 路径；人物、场景、动作视频或声音参考属于 Ref2VA 路径。不要再要求学员选择旧导演台的 `task_type`。
- 每张镜头卡是一次 4—15 秒 H3 生成。多卡时间线由节点串联；续接模式会把上一段解码后的尾帧交给下一段。不要把多卡时间线误写成一张卡内重复的长片总提示词。
- 工作流快照默认每段 6 秒、16:9、短边 768、20 步、CFG 1、`res_multistep`、`simple`。除非用户明确要改参数，否则只教学素材、镜头卡、时长与运行，不让零基础学员手工编辑 `creator_data` JSON 或改采样器、模型文件和线路。

### 旧版 Director 或独立 T2V/I2V/R2V 工作流

旧工作流仍按实际节点教学：Director 在 `global_prompt` 填写并先确认 `task_type`；独立工作流在实际 Prompt 字段填写。只有这些旧工作流才沿用界面显示的 `<Picture N>`、`<Video N>`、`<Audio N>` 序号。不要把旧 Director 的节点 ID、模型切换和填写方法套到单节点创作台。

镜像中当前独立 T2V、I2V、R2V 与 H3 视频修改工作流使用 `MiniMaxH3PromptRewriter`。保留工作流预设模式：若其 `prompt` 已连接上游文本节点，就在标题为“提示词”或 `Input Text (Prompt)` 的上游节点填写原始要求；没有连接时才直接填写重写节点内的 `prompt`。官方节点负责把原始要求重写为 H3 结构并输出校验报告，学员不要手工绕过它。报告出现未连接音频、引用越界或模式冲突时，先按实际素材连接顺序修正 `<Picture N>`、`<Video N>`、`<Audio N>` 引用，再运行生成。

`数字人音频驱动-升级版` 使用一张人物图和一段驱动音频。提示词只锁定画面中可见人物、表演幅度、口型与音频同步、镜头和背景连续性；实际对白、语气与节奏由音频决定，不在提示词里重写台词，也不要新增第二位说话者。

## 模式判断

先按素材的用途判断，不按文件数量猜：

| 用户意图与素材角色 | H3 模式 | 提示词结构 |
|---|---|---|
| 只有文字 | T2VA | Base |
| 一张图片作为首帧 | I2VA | Base |
| 首帧与尾帧各一张 | FL2VA | Base；默认单镜头连续插值 |
| 一张图片只作为尾帧 | L2VA | Base |
| 图片、视频或音频用于人物、服装、道具、场景、动作、风格或声音参考 | Ref2VA | 六段结构 |

同一张图不能同时被含糊地当作首帧和人物参考。单节点创作台中，先让用户在素材卡上选清“首帧/尾帧/参考”的角色；旧工作流中仍不清楚时再问一次。

## 共同输入与硬约束

- 每段时长为 4—15 秒整数；未指定时，单节点创作台沿用镜头卡默认 6 秒，其他 H3 工作流默认 8 秒。
- 画幅是工作流参数，不写入提示词正文；未指定时沿用工作流当前值。
- 参考项目安全上限：9 张图片、3 个视频、3 个音频，混合参考合计不超过 12 项；最终提示词不超过 7,000 字符。用户实际节点显示更小限制时，以节点为准。
- 最终模型提示词使用英文。用户原始对白、歌词和画面文字保持原语言与原标点，不翻译、不改写。
- 用户已经给出完整结构化提示词时，只检查模式、时长、引用顺序、时间覆盖、连续性和矛盾；除非修错，不要总结、缩短或换风格重写。

## 创作增强

在不偏离用户意图的前提下补足以下信息，但简单单镜头不必机械堆满标题：

1. 摄像机身份：手持、稳定器、轨道、无人机、固定机位等，以及必要的速度、幅度和真实瑕疵。
2. 视觉质感：材质、颗粒、色彩、主辅光源和跨镜头光线变化。
3. 节奏曲线：静到动、蓄势到爆发、高潮到收束，以及剪辑节拍。
4. 人物锚点：脸、发型、体型、服装、配件和可跨镜头识别的视觉标志。
5. 空间关系：左右、前后、进出方向、视线轴和关键动作向量。
6. 连续性：人物状态、服装、道具、环境、伤损和情绪如何继承。
7. 声音设计：环境声、动作音效、对白、可被角色听见的音乐与观众侧配乐。

每个镜头写清景别与角度、摄像机运动、一个主导动作、环境与光线、声音和结束状态。一个切镜必须带来新人物、新空间、新状态、新视点或新时间；只改变远近或轻微角度时用镜头运动，不切镜。

镜头运动写成自然动作句，包含类型、必要时的幅度和速度，例如：`The camera pushes in with small amplitude at slow speed toward the letter in her hands.` 不堆叠 `push in, cinematic, 4K` 一类标签。

## Base：T2VA / I2VA / FL2VA / L2VA

### 输出正文

最终可粘贴内容依次为：

1. 旧版 I2VA、FL2VA、L2VA 工作流需要的首尾帧对齐指令；单节点创作台由节点根据首帧/尾帧素材自动生成，不手写。
2. `integrated_multimodal_description:`
3. `overall_soundscape:`
4. `non_diegetic_music:`

T2VA 没有对齐指令。`overall_soundscape` 用 1—4 句描述全片环境声、动作声和非语言人声，不重复对白；`non_diegetic_music` 用 1—3 句写角色听不见的配乐乐器、速度、节拍和动态，没有配乐时写 `N/A`。

### 镜头预算与时间线

| 单段时长 | 建议镜头数 |
|---|---|
| 4—6 秒 | 1—2 |
| 7—10 秒 | 2—3 |
| 11—15 秒 | 3—5 |

- `[Shot 1]` 不写时间戳，先写整体风格和初始构图。
- 后续镜头写成 `[Shot N] At MM:SS.mmm, the camera cuts to ...`，时间严格递增且落在本段时长内。
- I2VA 从首帧的构图、身份、服装、道具、光线和空间关系自然起步，重点写随后发生的运动。
- FL2VA 默认单镜头，用可观察、因果连续的动作从首帧逐步落到尾帧；用户明确要多镜头时才切镜。
- L2VA 从合理的前置状态出发，在结尾逐步收敛并精确落到尾帧构图。

旧工作流的对齐行遵循用户提供规范中的固定句式；在单节点创作台中只选择正确的首帧/尾帧素材角色，避免手写重复对齐行。

## Ref2VA：参考生成

最终可粘贴内容严格按以下六段顺序：

1. `subject_definitions:`
2. `summary:`
3. `retention_analysis:`
4. `detailed_description:`
5. `overall_soundscape:`
6. `non_diegetic_music:`

### 引用与主体

- `<Subject N>` 表示可复用的可见主体：人物、动物、物体、场景、服装、姿势或风格。一个主体可由多份素材共同定义。
- `<Picture N>` 只表示具体首帧、关键帧、尾帧或构图锚点。只提供人物或风格的图片必须写进 `<Subject N>` 的来源，不单独把图片当主体。
- `<Video N>` 表示源视频、续写视频或整段镜头/节奏关系；视频中复用的人物仍定义为 `<Subject N>`。
- `<Audio N>` 表示音频信号、音色、台词、节拍或声音连续性。
- 旧工作流按界面序号引用；单节点创作台在提示词草稿中使用实际 `@` 句柄，节点排队时再转换为稳定的 H3 序号。不要把素材上传顺序当成主体编号。

`summary` 以一个或多个任务前缀开头：`[keyframe completion]`、`[reference generation]`、`[video editing]`、`[video continuation]`、`[audio reuse]`、`[audio reference]`。只参考镜头或节奏的视频属于 `reference generation`，不属于视频编辑。

`retention_analysis` 只能使用固定标记：视觉引用用 `fully_preserved`、`partially_preserved`、`attribute_transfer`、`weak_reference`；音频引用用 `fully_copy`、`partially_copy`、`reference`、`weak_reference`。新增动作、背景或剧情不等于引用损失。

`detailed_description` 的生成任务目标为 350—500 个英文单词。先用 1—2 句写整体风格，再进入 `[Shot 1]`；每个引用在第一次出现和实际生效处引用，主体身份与状态跨镜头保持一致。

## 对白、旁白、画面文字与音乐

- 说话人按首次发声顺序使用稳定 ID：`(S1)`、`(S2)`；从不发声的人物不分配 ID。
- 说话人身份、音色、语速和说话方式写在 `<d>` 外；`<d>` 内只放语言标签和用户原句，例如：`<d>[Chinese] 今晚的城市，像刚刚醒来。</d>`。
- 旁白使用明确短语 `says in an off-screen voiceover`，并紧接说明画面人物嘴唇完全闭合。
- 对白跨切镜时，两段连接处使用 `<scenetrans>` 并明确声音连续；被视频结尾截断时使用 `<cutoff>`。
- 招牌、字幕、界面和其他可见文字用英文双引号包住原文，不翻译。
- 角色能听到的电台、现场演奏、手机音乐属于画内音乐，写在镜头正文；角色听不到的配乐只写在 `non_diegetic_music`，同一音乐不能重复放两处。

## 交付与填写

- “可直接复制的提示词”代码块内只放模型提示词，不混入节点 ID、操作说明或 Markdown 围栏内标题。
- 代码块外说明检测到的模式、采用该模式的原因和必要假设。
- 单节点创作台的填写位置写：`MiniMaxH3Creator` → 对应镜头卡的大文本框；多卡共用约束才写顶部全局提示词。素材通过卡片内 `@` 选择器引用。
- 旧工作流按目录或用户 JSON 的实际节点标题、ID 和字段填写。用户界面与目录冲突时，以用户上传的 JSON 为准。

## H3 交付检查

- 工作流代际和模式判断正确，首尾帧没有被误当普通参考。
- 单节点创作台使用 `@` 句柄，旧工作流才使用固定 H3 序号。
- 每段 4—15 秒，时间戳递增且完整覆盖，镜头数与时长相称。
- 每镜头只有一个主导动作，镜头运动、环境、光线、声音和结束状态明确。
- Ref2VA 六段或 Base 三段结构完整，字段顺序正确。
- 人物身份、服装、道具、空间方向和状态连续。
- 对白原句未翻译或改写，画内音乐与配乐没有混用。
- 提示词不超过 7,000 字符，没有品牌、名人或第三方角色名被擅自加入。
