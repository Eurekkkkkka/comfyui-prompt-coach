# 逐段文字到视频闭环模式

当用户连续提交小说章节、书籍片段或剧情段落，并希望每段依次完成视觉资产、首帧图片、镜头视频和连续性验收后再输入下一段时，读取本文件。本模式继承 `novel-to-comic-pipeline.md` 的原著事实源、来源编号、项目状态和连续性规则，并继承 `visual-asset-storyboard.md` 与 `prompt-rules.md` 的资产和模型规则。

## 适用范围与边界

- 用户声明当前内容是完整短篇或全书时，可以先建立全局事实库；用户声明只是片段时，只对已提供内容下结论，结局、未出现设定和未回收伏笔使用 `unknown` 或低置信度。
- 每次开始新段落前先读取 `project-status.json`、`asset-registry.json`、上一段的 `state-after-segment.json` 和未解决连续性问题。不得重新发明已经批准的人物、场景、道具、音色或剧情状态。
- 用户可见的第一批交付可以是故事线和资产提示词，但 Agent 内部必须先完成本段事实提取、来源对应、连续性检查和资产缺口分析。
- 只生成当前段落新增或发生版本变化的资产。已有资产直接引用；换装、年龄、战损、损坏或昼夜状态变化建立新版本，不覆盖旧版本。
- 没有实际生成和回传的媒体时，只能称为提示词或交接文件。没有可检查素材时不得声称验收通过。

## 状态机

`project-status.json` 的当前阶段至少使用以下状态之一：

```text
待确认本段故事线与生成资产
待回传资产
待验收资产
待生成首帧
待回传首帧
待验收首帧
待生成镜头视频
待回传镜头视频
待验收镜头视频
本段完成
```

每次回复只推进一个门控阶段，并在 `NEXT_STEP.md` 写明用户现在唯一需要做的动作。

## 阶段 A：本段故事线与资产缺口

1. 为当前内容分配稳定段落 ID，例如 `SEG001`，保留章节和段落 `source_refs`。
2. 输出一份简短的本段故事线，包含进入状态、核心事件、冲突、转折、结束状态和与上一段的连接。先让用户确认文字逻辑，避免在剧情拆分错误时浪费图片算力。
3. 读取资产注册表，把本段所需内容分成：复用资产、新增资产、版本变化资产、待确认资产。
4. 在生成具体提示词前确认智算云扉中的完整图片工作流名称、模型变体、素材顺序和提示词节点。
5. 分别导出人物、场景和道具提示词。人物使用完整全身三视图，场景和道具每项只使用一张单图；中文长句和禁用词遵守 `visual-asset-storyboard.md`。
6. 新角色需要独立建立声音档案，但声音不列入第四类视觉资产。把音色、年龄感、语速、情绪范围、发音和参考音频登记到 `voice-bible.json`。

首批用户可见文件默认使用：

```text
第01段-故事线摘要.md
第01段-人物资产提示词.csv
第01段-场景资产提示词.csv
第01段-道具资产提示词.csv
```

质量门：故事线与原文来源对应，资产复用与新增范围清楚，具体工作流已经确认，提示词能够直接填入真实节点。完成后只提醒用户在智算云扉生成资产并回传图片或资产联系表。

## 阶段 B：资产回传与验收

用户回传资产后实际检查：

- 人物是否为同一角色、同一年龄与服装版本的完整全身正面、标准侧面和背面，头脚没有裁切。
- 场景是否为一张单一连续空间画面，入口、地标、材质、时间、光线和纵深是否清楚，没有三视图、分栏、拼贴或重复地标。
- 道具是否为一张单物体参考图，轮廓、材质、颜色、纹样、尺寸关系、损伤状态和佩戴方式是否清楚，没有复制主体、分栏或拼贴。
- 资产是否出现额外人物、乱码、水印、结构变形或与原著冲突的内容。

把通过的文件登记到 `asset-registry.json`，记录 `asset_id`、版本、来源、文件路径、工作流和验收状态。输出 `第01段-资产验收报告.md`。任一关键资产不通过时停留在本阶段，明确本轮只修改的变量。

如果用户只说“资产做好了”但没有回传图片，状态写为“用户确认、未经 Skill 视觉验收”；可以继续，但在首帧和最终质量报告中持续保留风险提示。

## 阶段 C：分镜表与首帧图片

只有本段故事线已确认且所需资产已通过或被用户明确接受风险后，才能生成分镜。分镜必须基于已批准的文本改编，不得从资产图反向改写剧情。

`第01段-分镜表.csv` 至少包含：

```text
段落ID｜镜头ID｜叙事目的｜时长｜景别｜机位｜动作｜表情
人物资产ID｜场景资产ID｜道具资产ID｜开始状态｜结束状态
图片工作流｜首帧提示词｜尾帧需求｜来源编号｜验收状态
```

同时导出 `第01段-首帧提示词.csv`。每个镜头明确引用哪些人物、场景和道具资产；首帧提示词写静态可见事实、站位、视线、构图和光线，不把完整视频动作时间线塞进首帧。若已确认的视频工作流需要首尾帧，另外生成必要的尾帧提示词；不得默认所有工作流都只需要首帧。

完成后只提醒用户在智算云扉生成首帧或首尾帧并按稳定文件名回传。

## 阶段 D：首帧回传与视觉故事线验收

把所有首帧按镜头顺序检查，完成第二次故事线验收：

- 顺序排列后是否能看懂本段故事，镜头是否遗漏关键因果或重复表达。
- 人物身份、年龄、服装、伤势、位置和视线是否连续。
- 场景空间、昼夜、天气、光源和地标是否连续。
- 道具是否复制、消失、换手、改变损伤状态或无来源新增。
- 上一镜头结束状态是否能自然进入下一镜头开始状态。

输出 `第01段-首帧验收报告.md`。阻断问题未解决时不生成视频提示词；失败重跑遵守单变量原则。

## 阶段 E：逐镜头视频提示词

首帧通过后，先确认每个镜头实际使用的视频工作流和任务类型：

- T2V 不使用首帧。
- I2V 使用首帧作为人物和场景锚点。
- FL2V 使用首帧和尾帧，提示词描述两端之间的连续过程。
- R2V、V2V、RV2V 必须逐一声明图片、视频和音频参考的职责。
- 对口型或带声音工作流还需要角色声音、台词或参考音频。

导出 `第01段-视频提示词.csv`，至少包含：

```text
段落ID｜镜头ID｜视频工作流｜任务类型｜输入素材及职责
时长｜动作时间线｜表情与视线｜场景动态｜镜头运动
结束状态｜声音与对白｜连续性限制｜输出文件名｜状态
```

输入图片已经定义人物和场景时，视频提示词重点写“接下来发生什么”，不得重复改写静态外貌。相邻镜头的结束状态和开始状态必须能够衔接。

## 阶段 F：视频回传与最终验收

用户回传镜头视频后，检查：

- 单镜头内部动作、表情、肢体、镜头运动和结束状态是否自然。
- 相邻镜头之间人物身份、服装、位置、视线、伤势、场景和道具是否连续。
- 角色音色、说话人、语速、情绪、对白内容和口型是否一致；没有音频时明确标为未验收，不得声称音色通过。
- 是否存在闪烁、跳变、额外人物、道具复制、字幕水印、无动机切镜或意外音乐。

输出 `第01段-视频验收报告.md`。失败镜头只修改一个已声明变量并保留失败版本、重跑版本和对比结论。

## 阶段 G：本段完成与续作

所有阻断问题关闭后：

1. 更新 `asset-registry.json`、`voice-bible.json`、`project-status.json`、`deliverables-manifest.json` 和跨段连续性问题。
2. 写入 `state-after-segment.json`，记录人物、地点、道具、关系、伤势、秘密、伏笔、声音和时间线的结束状态。
3. 输出 `第01段-完成状态.json` 和必要的最终报告；中文文件供用户查看，英文状态文件供 Skill 续作。
4. `NEXT_STEP.md` 只写：本段文字到视频生产已经完成，请输入下一段小说内容。下一段自动继承已经批准的人物、场景、道具、音色和剧情状态。

## 中文命名规则

用户可见交付物默认使用中文文件名，系统状态文件保持稳定英文名。中文文件名使用两位数段号、三位数镜头号和版本号，避免 `\ / : * ? " < > |`，避免结尾空格或句点。

建议目录：

```text
第01段/
├─ 01-故事与资产/
│  ├─ 第01段-故事线摘要.md
│  ├─ 第01段-人物资产提示词.csv
│  ├─ 第01段-场景资产提示词.csv
│  ├─ 第01段-道具资产提示词.csv
│  └─ 第01段-资产验收报告.md
├─ 02-分镜与首帧/
│  ├─ 第01段-分镜表.csv
│  ├─ 第01段-首帧提示词.csv
│  └─ 第01段-首帧验收报告.md
├─ 03-镜头视频/
│  ├─ 第01段-视频提示词.csv
│  └─ 第01段-视频验收报告.md
└─ 第01段-完成状态.json
```

媒体文件示例：

```text
人物-林凡-常服-全身三视图-v01.png
场景-青云山门-单图-v01.png
道具-玄铁剑-单图-v01.png
第01段-镜头001-雨夜山门-首帧-v01.png
第01段-镜头001-雨夜山门-视频-v01.mp4
第01段-镜头001-林凡配音-v01.wav
```

文件内容继续使用 `SEG001`、`SH001`、`CHAR001`、`LOC001`、`PROP001` 等稳定 ID。人物改名或文件名调整时不改变 ID；所有引用关系以内部 ID 为准。
